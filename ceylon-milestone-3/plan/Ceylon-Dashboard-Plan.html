Plan for review · 25 Nov 2026

Ceylon Nooks dashboards: one system

Before the refund screens are designed, this plan sets out how the partner and admin dashboards become one system. The refund screens come first and use it, and every other screen moves into it later in stages. It builds on what already exists: the partner onboarding style guide (Sep 2026) and the refund screens on your Claude canvas.

1Inventory

Every screen in both portals, what it's for and the patterns it uses. The same ten patterns repeat everywhere.

2One shell

One layout for both portals: side menu, top bar, page header, filters, side panel, toasts. Partner and admin only differ in their menu.

3Components

Built in Figma with auto layout, starting with what the refund screens need: pills, rows, cards, tabs, panel, timeline, money breakdown, countdown, fields, buttons, dialogs.

4Tokens

The style guide's colours, type, spacing and radius, kept and named once, so developers map them in code one time.

5Status language

One list of statuses with the same names and colours for traveller, partner and admin. Red only ever means “you need to act now”.

6Redesign map

Every existing screen with what changes and how big the change is, split into now (refund work), next and later.

What we found. The two portals have different logos, menus, headers, tables and status pills. On a phone, six partner pages have tables 640 to 970 px wide on a 390 px screen, so they scroll sideways. Partners mostly work from their phones, so every table also gets a phone card layout, and the phone version gets a bottom tab bar, because it will be used as an installed app for about a year.
What we kept. The style guide's colours already match the traveller site, and its fonts (Bricolage Grotesque and Manrope) are already built, so we keep both. We tidied two small things: one green for “success” (the refund screens used a second, slightly different green) and a neutral grey for closed items.

4 · Tokens

Kept from the style guide, named once

These are the same --cn-* colours the traveller site already uses, so all three products match. Developers map each token in code one time. Dark values come from the traveller site's dark mode.

Brand and neutrals

Use tokens, never raw hex. Orange text on white always uses Primary text (#C43D12) for contrast.
